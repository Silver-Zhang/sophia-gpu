# 第三章 GPU加速确定论中子输运计算方法

## 3.1 国内外研究现状

### 3.1.1 MOC数值方法及三维实现

MOC沿特征线作局部解析积分。在平源、段内截面恒定时，入射与出射角通量满足@eq-moc[@r6]。

$$\psi_{\mathrm{out}}=\psi_{\mathrm{in}}e^{-\Sigma_t\ell}+\frac{Q}{\Sigma_t}(1-e^{-\Sigma_t\ell})$$ {#eq-moc}

其中ℓ为段长，Q为给定迭代中的角源，Σ为总截面。真空极限应连续趋于入射角通量加Qℓ，数值实现需避免小光学厚度下的消减误差。直接三维MOC沿三维轨迹积分；MOC-EX、平面MOC/HFEM、DGMOC及MOC/DD的轴向处理各有不同。Gaston等证明非结构网格三维MOC可处理更一般几何；这与利用轴向挤出结构减少存储的实现形成不同取舍[@r7]。

### 3.1.2 CPU/MPI与GPU并行特征线输运

单条轨迹内部存在沿程依赖，多条轨迹在给定源和相应边界迭代条件下可提供大量并行任务。宋佩涛博士论文及系列工作讨论二维并行粒度、性能模型、MPI/GPU通信掩盖、CPU/GPU负载分配及MOC-EX与CMFD，形成ALPHA研究路线[@r19; @r20]。Li等的ANT-MOC利用存储、计算、通信模型及多级负载映射实现大规模多GPU三维输运[@r21]。汪岸博士论文与Wang等循环轨迹分解研究进一步说明负载估计应考虑轨迹长度分布，而非只平均分配轨迹数量[@r22; @r23]。

### 3.1.3 轨迹存储、在线生成及计算负载优化

显式保存可以减少重复几何计算，但存储全部三维段容易受显存限制；在线生成以额外追踪换取存储空间，部分缓存则在两者之间配置数据。Zhou等比较在线生成、显式轨迹和分组均衡，其在线轴向追踪利用二维轨迹和轴向挤出结构[@r24]。Song等在直接三维MOC中结合源近似、在线轴向追踪和批处理缓解显存需求；Dzianisau与Lee采用轴向分解、异步执行和MOC/DD[@r25; @r26]。这些工作支持受控比较存储策略，但不意味着同一种策略适用于任意聚变三维几何。

### 3.1.4 GPU-MOC显存管理与性能建模

显存不仅用于轨迹段，还包括源项、标量/角通量、散射矩、边界数据和求解器工作区。ANT-MOC将存储、计算与通信共同建模，NuDEAL针对不同离散采用压缩角通量和方位角顺序扫描[@r21; @r27]。NVIDIA文档强调合并访存、数据复用及同步成本，warp聚合原子操作展示减少竞争的一般技术[@r28; @r29]。这些机制需结合MOC实际访问模式验证：减少原子次数可能增加局部工作区，压缩存储可能改变数值精度，均应纳入成本与误差分析。

### 3.1.5 GPU确定论正向及伴随输运的相关研究

正向和伴随问题共享轨迹、截面与空间结构，但伴随涉及散射转置、能群耦合方向及对应边界条件。现有GPU论文主要给出堆芯正向或本征值求解性能；是否提供可用于CADIS的固定源伴随接口，需要按具体实现核实。NuDEAL中的MOC/HFEM、DGMOC受轴向挤出条件约束，一般多面体能力来自DFEM-S_N，不能把整个框架统称为任意几何三维MOC[@r27]。成熟减方差系统的正/伴随流程可作为数值一致性参照[@r40]。

### 3.2.3 已有求解器对固定源及伴随问题的支持情况

多数GPU-MOC工作以临界本征值、组件功率或全堆芯计算为主要验证场景；聚变屏蔽则常为高能源固定源和局部小响应。需要检查外源归一化、上散射及相关次级产生、各向异性散射与真空边界，并以固定源算例验证。正向GPU能力不自动等于伴随能力；若已有软件缺少离散伴随或核数据接口，方向二的工作量将明显增加。MAVRIC或OpenMC的伴随驱动权窗流程提供成熟任务参照，但不直接替代新MOC算子的正确性检验[@r40; @r41]。

## 3.3 初步研究思考

### 3.3.1 GPU并行方法能否降低复杂三维确定论预计算成本？

拟比较从输入更新到可用正向/伴随场的完整时间，并区分源项更新、材料更新和几何更新。GPU收益可能随计算规模、迭代次数与数据驻留程度变化；轨迹只使用少量次数时，建缓存的成本可能无法摊销。假设是特定任务组织在一定规模和更新类型下缩短预计算，而非GPU在所有条件下更快。测量以优化多核CPU与可访问GPU实现为基础，并记录编译、精度与计时边界。

### 3.3.2 非均匀网格与GPU轨迹执行之间存在怎样的成本关系？

拟把网格与轨迹策略作为联合变量，比较均匀细网格和局部网格分别配合在线、全缓存及部分缓存的最合适配置。调参预算保持对等，正式算例与调参算例分开。随后固定代表配置，通过分组与归约消融识别交互作用。若块定位和工作不均衡抵消段数减少，应报告无时间收益的条件，而非将未知量减少解释为加速。

### 3.3.3 如何在伴随求解精度与预计算成本之间取得平衡？

伴随精度首先应满足正—伴随一致性和目标相关收敛检验，再考察更细离散是否有足够的蒙卡收益抵偿成本。拟以相同探测器和物理源建立一组由粗到细的重要性场，固定权窗生成规则，测量预计算与蒙卡时间；另行改变映射和权窗参数，定位收益来自何处。若伴随细化只改善确定论误差而不改善统计任务，适宜停在较低成本配置。

## 3.4 可能开展的研究内容与关键技术

### 3.4.1 GPU-MOC轨迹与数据结构设计

以可修改MOC实现为前提，整理源区、材料、能群和轨迹段的访问关系，建立在线生成与缓存共享的几何核。按实际段数或估计工作量分组，比较轨迹—能群任务组织和不同数据布局。部分缓存按资源预算配置，其容量由预实验决定。先保证各路径生成相同材料序列，再比较数据量和时间，避免把数值改变混入执行优化。

### 3.4.2 并行扫描、归约与显存管理

扫描保持单条轨迹沿程依赖，源区通量由轨迹积分和求积权重归约。拟比较直接原子累加与线程块内局部归约，再检查临界区竞争、浮点累加次序和工作区开销。峰值显存通过运行时测量核实，并包含通信及求解器临时缓冲。异步传输或重叠执行须用同步完成后的计时验证，同时保留独立分项剖析，以免把等待时间移出测量范围。

### 3.4.3 正向—伴随计算能力及数值正确性验证

先验证纯吸收、真空极限、均匀介质和跨界段，再做多群散射与伴随测试。离散层面以体积、角权重构成加权内积，检查离散算子与其伴随的对偶关系，以及正向响应与伴随源响应的一致性；反向追踪本身不足以完成该检验。CPU/GPU结果比较须同时考察守恒、局部响应和精度敏感性。通过后再把伴随场用于权窗，避免以蒙卡减方差有效间接代替伴随正确性。

### 3.4.4 GPU计算性能与资源适用性分析

记录前处理、扫描、归约、源更新、迭代、传输及输出时间，按实际发生次数构成方案周期。首次运行、数据可复用更新和需重建更新分别报告；硬件间比较注明核数/GPU数、内存、精度和收敛标准。预期成果是可由段数分布、资源预算和更新类型解释的执行选择依据。若代码接口或GPU资源无法落实，则应调整候选方向；现有Python/C++与输运建模经验提供学习基础，申请人仍需系统补足GPU编程和MOC实现能力。
