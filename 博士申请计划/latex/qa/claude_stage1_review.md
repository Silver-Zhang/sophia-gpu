## 一、当前计划中应补齐的保护措施

### 1. 建立不可变的基准清单，而非只依赖口头数量

应将提交 `90694990d1717da06eafc59f4cc25081a74f9cb5` 作为唯一内容基线，并在 `latex/qa/` 生成、版本控制下列机器可比对文件：

- 67 条文献的：
  - `key` 集合；
  - 逐条正文或规范化后的哈希；
  - 文献总数；
  - 引用键在正文中的出现次数。
- 9 个编号公式的：
  - 标签集合 `eq:1` 至 `eq:9`；
  - 公式源文本或规范化哈希；
  - 所在章节、前后解释段的定位信息。
- 7 幅图、6 张表的：
  - 标签集合；
  - 图表源文件路径；
  - 标题、交叉引用、正文解释位置。
- 六个原章节到 V5 六章的映射表。
- 编译后的：
  - PDF 页数；
  - 未定义引用数；
  - 未定义文献数；
  - LaTeX Error 数；
  - 关键 warning 白名单。

仅检查“仍有 67 条”“仍有 9 个公式”不够。例如，删除原 `eq:7` 后新增一条无关公式，数量仍然是 9，但数学证据已经丢失。

### 2. 对“保护”明确分级，避免误把重排当作删减

建议将受保护对象分为三类：

| 级别 | 对象 | V5 中允许的操作 | 不允许的操作 |
|---|---|---|---|
| A：语义/文本强保护 | CADIS/FW-CADIS 恒等式、成本定义、原表3和原表4 | 移章、补充解释、统一符号时在原式附近保留等价原式 | 删除、改写成不等价形式、只保留文字转述、仅在附录残留且正文失去解释 |
| B：数学/数值证据保护 | 9 个编号公式、图表中的定量数据、性能或误差结论 | 重编号、重排、增加推导和限定条件 | 用概念性描述替代公式/数值证据；更改数值却无来源和说明 |
| C：文献资产保护 | 67 条文献及其关键论证角色 | 重排、改为更合适章节引用 | 无故删条、替换为较弱来源、保留条目但正文完全失引 |

特别要求：**原表3、原表4必须以“来源表号—V5 表号”的映射受控**。V5 可以改变表号，不能让“保护原表3/4”在实际操作中变成无法验证的要求。

### 3. 固化 CADIS/FW-CADIS 与成本定义的验收点

这三项不能只做全文关键词搜索，应明确为独立验收项：

1. CADIS 相关源项、伴随解、重要性函数、权窗/源偏置的关系式是否完整；
2. FW-CADIS 的全局响应构造及其与 CADIS 的差异是否仍被准确表达；
3. 原有“成本”定义的符号、量纲、统计量口径、比较对象是否保留；
4. 恒等式和成本定义是否仍有：
   - 编号公式或明确可引用公式；
   - 变量定义；
   - 紧邻的物理/数值解释；
   - 对应参考文献，至少覆盖 `ref4`、`ref5`，并保留与 MAVRIC/ADVANTG 或混合减方差相关的支撑文献。

若 V5 将减方差降为“应用”，正确做法是把这组内容集中在第5章，并在第4章只保留与协同优化有关的接口说明；不能因其不再是主研究问题而将数学定义压缩成一两句综述。

## 二、V5 重构计划可能遗漏的内容

### 1. 六章标题与三条研究问题之间需要一张显式闭环表

目前目标结构已经有六章和三条研究问题，但仍需确认每个研究问题均包含：

- 科学/工程问题；
- 核心方法；
- 可检验假设；
- 对照方法；
- 指标；
- 验证算例；
- 预期产出；
- 与后续章节的输入输出关系。

建议在第4章开头放置“研究问题—方法—指标—验证”表。至少应覆盖：

| 研究问题 | 需要明确的技术对象 | 最低验收指标类别 |
|---|---|---|
| 复杂几何体素化与特征线输运 | CAD/复杂边界到体素材料场、特征线生成与追踪、几何近似误差控制 | 几何保真度、区域/材料识别误差、通量/反应率误差、线追踪与建模开销 |
| GPU-MOC 并行计算 | 数据布局、轨道/特征线调度、核函数划分、访存和分歧控制、收敛迭代 | 吞吐率、加速比、并行效率、显存占用、可扩展性、数值一致性 |
| 两者协同优化 | 体素分辨率、材料压缩、特征线密度、分组/角度离散与 GPU 执行代价的共同选择 | 给定精度下总时间/总成本最小，或给定成本下响应误差最小 |

如果没有这张闭环表，V5 容易重回“几何综述、GPU综述、减方差综述”并列堆砌，而“协同优化”成为没有可验证内容的口号。

### 2. 第2章不能只写体素化综述，必须保留 MOC 的数值链条

V5 题目明确以“体素化特征线中子输运”为核心。第2章的最低完整链条应为：

```text
复杂 CAD/几何模型
  → 体素化与材料赋值
  → 体素边界上的特征线分段/轨迹追踪
  → MOC 空间与角度离散
  → 多群源迭代/特征值或固定源求解
  → 通量、反应率、屏蔽响应
```

计划中应显式核查下列容易遗漏的问题：

- 体素分辨率与薄层、狭缝、曲面、材料界面的保真关系；
- 阶梯化误差、部分体积/混合材料处理、空洞和重叠几何规则；
- 特征线穿越体素时的分段长度计算及累计误差；
- 体素尺寸、特征线间距、方位/极角、能群数之间的误差耦合；
- MOC 的边界条件、源迭代/加速、收敛判据；
- 用于聚变屏蔽时的固定源、深穿透、强各向异性问题；
- 与 CAD 直接追迹、非结构网格、八叉树/自适应 Cartesian 网格方案的边界和取舍。

这部分是 V5 的主线，不能因第2章采用“综述”命名而失去公式、误差来源和数值证据。

### 3. 第3章需从“GPU 技术综述”升级为可落地的 GPU-MOC 设计

仅列出 CUDA、OpenACC、GPU-MOC 文献不足以支持研究计划。后续草稿至少应给出拟解决的并行粒度和数据流：

- 并行对象是特征线、线段、空间体素、角度、能群、源迭代，还是其组合；
- 轨迹长度与材料边界差异导致的负载不均衡如何处理；
- 分支发散、随机/非连续访存、累积更新/原子操作如何评估；
- 轨迹数据预生成与在线生成之间的显存—计算权衡；
- 材料截面、角通量、标量通量、轨迹/线段描述符的数据布局；
- 单 GPU 的基线实现与必要时的多 GPU 扩展边界；
- CPU、CPU-GPU 异构和已有 GPU-MOC 的公平比较口径；
- 数值一致性、可重复性和性能测试的硬件、编译器、精度设置。

`ref24`–`ref38`、`ref26`–`ref27`、`ref29`–`ref30` 可支撑该章，但文献引用应落实到上述设计决策，而不是作为罗列。

### 4. “协同优化”必须定义优化变量、目标和约束

第4章是 V5 与 V4.2 最关键的结构变化，也最容易空泛。建议明确至少一种可执行表达，例如：

\[
\min_{\Delta x,\; h_{\mathrm{track}},\;N_\Omega,\;N_g,\;\mathcal{S}}
T_{\mathrm{GPU}}(\cdot)
\quad
\text{s.t.}\quad
\epsilon_R(\cdot)\leq \epsilon_R^\ast,\;
M_{\mathrm{GPU}}(\cdot)\leq M^\ast .
\]

其中不必现在承诺最终算法，但必须在计划中说明：

- 体素尺度、轨迹间距、角度离散、能群、数据压缩/调度策略中哪些是协同变量；
- 响应误差用何种基准定义；
- 总成本是否包括预处理、体素化、轨迹生成、GPU 求解和后处理；
- 面向单个算例、参数扫描还是屏蔽设计迭代；
- 如何避免“体素更细—误差更小—显存爆炸”仅被定性描述。

原有成本定义若与此处的总成本指标不同，应并列说明两者用途，不能静默替换。

### 5. 第5章的验证链条需要分层，而非直接进入大型聚变算例

建议将第5章验证按三层编排：

1. **方法验证**：规则几何或可解析/高精度参考问题，验证体素化、特征线追踪和 MOC 离散误差；
2. **复杂几何验证**：具有曲面、薄层、孔道或多材料界面的 CAD/体素模型，验证复杂几何处理；
3. **聚变屏蔽应用**：FNS/SINBAD 或与聚变屏蔽相关的基准，比较关键响应、深穿透区域统计品质和总计算成本。

给定基准文献中已有 `ref1`、`ref59`–`ref63`，以及 CAD/混合方法和减方差文献，V5 应明确：

- 使用哪个具体 SINBAD/FNS 基准及响应量；
- 确定论体素-MOC 的参照结果来自何处；
- 蒙特卡罗耦合时的比较指标；
- CADIS/FW-CADIS 作为**应用**时，怎样证明其输入的重要性/伴随量受 V5 主方法支持；
- 不把确定论误差误归因于减方差效果，不把蒙特卡罗统计误差误归因于体素化误差。

### 6. 第6章应是博士工作安排，不应成为“候选方案”残留

原第6节为“候选方案”，V5 第6章改为“博士工作安排”时应明确检查：

- 原候选方案中仍有价值的路线、风险和备选措施是否迁移；
- 任务按“几何/MOC—GPU-MOC—协同优化—验证/减方差应用”依赖关系排序；
- 每一阶段有可交付物，而非只有年份；
- 关键风险至少包括：
  - 体素化误差难以满足屏蔽响应精度；
  - 轨迹数据规模超过显存；
  - GPU 加速受不规则访问与负载失衡限制；
  - 复杂聚变算例缺少可比高保真参考；
  - MOC 产生的伴随解不适合作为减方差参数时的降级方案。

## 三、67 条文献的迁移核查重点

### 1. 不只检查总数，检查“键、条目、角色、引用”四层一致性

后续阶段应分别验收：

```text
67 个 key 完整存在
+ 67 个条目内容未被静默劣化
+ 每条保留文献在 V5 中仍有合理论证角色
+ 所有正文引用均可解析
```

尤其应警惕以下两类错误：

- `references/` 是未跟踪目录，构建时可能读到本地新文件，但提交后或他人检出时无法复现；
- 新增文献后总数仍写作“67”，但实际出现重复 key、替换条目或被遗忘的旧条目。

如“保留67条”意味着**恰好保留原 67 条**，应禁止替换和新增；如允许新增，则应明确要求“原 67 条逐条保留，新增条目另计”，并将验收目标改为“原 key 集合为子集”。

### 2. 建议按论证角色检查文献簇

| 文献簇 | 应在 V5 的主要落点 |
|---|---|
| `ref1`–`ref12` | 复杂几何、CAD、Cartesian/体素、自适应空间离散 |
| `ref13`–`ref23` | MOC、非结构/自适应离散及误差控制 |
| `ref24`–`ref42` | GPU-MOC、GPU 确定论输运、并行实现与性能约束 |
| `ref43`–`ref58`、`ref67` | CADIS/FW-CADIS、混合方法、自动减方差与应用边界 |
| `ref59`–`ref63` | 聚变屏蔽、SINBAD/FNS、ITER 相关验证 |
| `ref64`–`ref66` | CAD/射线追踪、SDF、MOC 轨迹与内存管理 |

特别是 `ref64`–`ref66` 在所给清单末尾，容易在迁移中成为“存在但未使用”的孤立条目；它们恰好可支撑 V5 的复杂几何射线追踪、体素/几何接口和 GPU 内存管理论证。
